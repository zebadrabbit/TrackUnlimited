01

What makes this different

A

Numeric, formula-driven track authoring

No click-drag-place viewport editing. A track is an ordered list of typed parametric segments — straight, constant-radius curve, clothoid transition, helix — each defined by values or expressions. The 3D view is a read-only preview, not the editing surface. It diffs in version control, because it is data.

B

Curvature continuity as a property of the data

A segment carries curvature varying linearly over arc length, and geometry comes from integrating a moving orthonormal frame along that profile. C² continuity is therefore something the representation guarantees rather than something fitted afterwards, and transition curves are the native case instead of special handling.

C

Real block signalling, not "train present / absent" PHASE 3

Designed and prototyped, not yet wired into the ride. Every block is a state machine — CLEAR → OCCUPIED → BUFFER(x) → CLEAR — where the buffer is the safety overlap a block holds after a train has physically left it. Dispatch permissives read forward through the block list. Automatic and manual dispatch modes change who decides the timing, never whether the interlocks apply.

D

A control panel generated from the coaster's own data PHASE 3

The design, for when the signalling lands. Not a cosmetic prop: walk the same ordered block and segment list that will drive the mesh and the physics: each block emits an indicator, each powered segment emits a VFD module with target speed, motor feedback, torque and ramp rate. The causal chain is visible — sensor trips, indicator lights, logic evaluates, actuator responds.

03

The hard parts, prototyped first

Five standalone prototypes, plain C++17 with no engine dependency — they build and run without an Unreal install, which is the lowest-friction way into the codebase and keeps the maths from quietly depending on engine behaviour.

TrackSpline

Curvature-continuous track geometry. Segments are curvature profiles over arc length; heartline-relative banking and felt G come out of the same frame.

GEOMETRY · C++17

TrainPhysics

1D train motion along that track. Gravity is an exact energy exchange rather than an integrated force, so a frictionless circuit conserves energy at any timestep.

SIMULATION · C++17

BlockSignal

The CLEAR → OCCUPIED → BUFFER(x) → CLEAR state machine and the dispatch permissive logic, with unit tests.

SIGNALLING · C++17

NL2Csv

Reads and writes NoLimits 2's documented spline export, so real layouts can be driven through the model. A validation path, deliberately not an authoring path.

VALIDATION · C++17

NL2Telemetry

Live telemetry capture, so the model can be checked against an independent simulator rather than only against closed forms.

VALIDATION · C++17

In-engine vertical slice

The reference layout builds clean against UE 5.8.1, rides, and reads out speed and G on screen — from the same headers the standalone assert suites test. The train has length, and you can pick a seat.

UE 5.8.1 · PHASE 0

Editor, undo and save format

The track is a typed segment list in the Details panel with snapshot undo, a diffable JSON save format that stores what was authored rather than what was derived, a damped Gauss-Newton closure solver, and self-clearance checking.
