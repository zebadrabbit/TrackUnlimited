# CLAUDE.md

Instructions for Claude Code (or any other AI coding agent) working in this repository. Read this before writing or changing anything.

## What this project is

TrackUnlimited: a free, open-source, Unreal Engine 5 roller coaster simulator built as a successor to NoLimits 2 — engineering-grade physics and track precision, a modern approachable UI, and a real block-signaling/ride-control system neither NoLimits 2 nor Planet Coaster has. Solo-developer-led. PC flatscreen first; VR is a deliberate later phase.

## Non-negotiable architectural constraints

These were deliberate decisions made after discussion, not defaults — do not "helpfully" change them without raising it first.

1. **No viewport click-drag-place track editing, ever.** Track segments are numeric/formula-driven parametric data (straight, constant-radius curve, clothoid transition, helix), each defined by typed values/expressions. The 3D view is a read-only preview, not the editing surface. This was an explicit rejection of the Coaster Forge / Satisfactory-style direct-manipulation model — do not add drag handles "for convenience" or "for a quick prototype."
2. **C++ for physics and signaling.** Blueprint is fine for editor tooling, UI, and rapid iteration on non-critical systems, but the energy-based motion model (Section 5, "Physics simulation") and the block-signaling state machine (Section 5, "Signaling and ride control") must be C++.
3. **No dependency on Train and Rail System (Polygon Jelly) or any other paid marketplace asset in committed/shipped code.** It's reference material the developer used while prototyping locally — never to be redistributed or have its code/assets copied into this repo.
4. **No Unreal Engine source in this repo, ever.** Project code and content only, per the UE EULA. Contributors get the engine themselves via Epic Games Launcher or their own linked GitHub access.
5. **No real manufacturer trademarks or exact ride designs** (Vekoma, Intamin, B&M, RMC, etc.) without explicit permission. Use original/generic naming and designs.
6. **MIT license** on everything committed here (see `LICENSE`).
7. **Three tiers, and requests never travel down. DECIDED 2026-08-06.** Safety is C++ and is **not scriptable, not overridable, and has no debug bypass that ships** — the E-stop chain, restraint proof, gate interlocks, overspeed, anti-rollback, block veto. Control (dispatch policy, sequencing, device commands) and Show (lights, audio, effects, cameras) sit above it and may **ask** the tier below for something and be refused; they may never grant themselves anything. This is not invented: Alcorn McBride state in their own manual that show equipment "is not intended for use in applications where a malfunction can reasonably be expected to result in personal injury", and nothing that can hurt a guest fires from a show controller alone. **It answers structurally, rather than by policing, the question every user-scripting system faces — can a downloaded track make the ride dangerous?** No, and not because scripts are validated well: because the layer that could is not scriptable, for the same reason it isn't in a real park. **SHOW IS READ-ONLY** and makes no requests at all — it subscribes to the state-transition stream and writes to fixtures, which is also how DMX512 works on the wire. Hazardous effects are gated by a hard permissive they cannot see or influence: a show controller fires into a circuit that may be open and does not know. **TIER 2 GETS EXPRESSIONS, NOT STRUCTURED TEXT. DECIDED 2026-08-06.** An override is a pure expression over a named process image — no statements, no assignment, no loops, no state across scans — evaluated against the snapshot the scan already takes. Written in **strict ST spelling from day one** (`AND`/`OR`/`NOT`, `=` for equality, `<>` for inequality, `SEL(cond, false, true)` rather than a ternary) so it is a genuine subset and a later ST is an *extension* rather than a replacement. Roughly 900 lines, and **the process image is the larger half of it** — Tier 2 needs that whichever language wins, so none of the work is speculative. **The safety rule is structural, not policy: an override may only make a permissive MORE restrictive.** It is an extra `AND` term on the existing chain, so there is no syntax for loosening one and no review needed to be sure — which is what makes an override from a downloaded track safe by construction. What it cannot express is **state and sequencing**: *"run forward 4 s, then reverse, then park backwards"* needs variables that persist across scans, and the day something wants that is the trigger for revisiting ST. Nothing built or planned needs it — shuttles, turntables and transfer tracks are all unbuilt or parked — and the C++ default program has absorbed every ride type attempted so far, including the small-batch platform, which turned out to be mostly emergent. **TIER 2 IS BUILT (2026-08-06):** `PlcImage.h` is the process image — 73 named slots on the two-train circuit, **declared from the layout** so an override written for another track fails to BIND, and **generated rather than maintained** (`Describe()` enumerates every slot, and the suite asserts each one binds back to itself, so autocomplete and the docs cannot drift). `PlcExpr.h` is the lexer, precedence-climbing parser and pure evaluator. **`Restrict()` is the only entry point and it is one `&&`** — five deliberately hostile always-TRUE expressions are asserted to grant nothing. A **broken override leaves the permissive UNCHANGED** rather than denying, or a typo in a downloaded track is a denial of service. Types are checked at parse time, and the C spellings (`!=`, `&&`, `? :`) are REFUSED — which is what keeps it a subset rather than a dialect. `Docs/TIER2_OVERRIDES.md` is the reference and **every example in it is parsed and bound in the assert suite**, so a stale one fails the build rather than somebody's evening. **Tier 3's language stays open** and is answerable once cues exist; `FShowBus` is the boundary and needs no language at all.

## The control layer is a LAYER OF CHOICE, and an on-ramp

Settled 2026-08-06, and it governs every UI decision the shell work is about to make.

**Nobody should ever have to open the control layer to have a working, exciting ride.** Every preset runs on the generated C++ default: place track, it works, trains dispatch, blocks interlock. Tuning is numbers in a panel. An expression override is for the case the default will not do what somebody wants. Nothing above that is ever required.

**So the risk is presentation, not architecture.** A `PROGRAM` tab in the main navigation says "you need this". A first-run experience showing a controlword says "this is for engineers". The depth alienates nobody as long as it is *findable by someone who wants it and invisible to someone who does not* — which is the same progressive-disclosure rule already applied twice, in `EditConditionHides` and in the operator/maintenance panel split.

**And the depth is meant to be worth learning.** The developer's framing, and it is the better one: *it should spark interest that could lead to a career decision in the real world.* Industrial control is a real, understaffed, well-paid field that almost nobody discovers as a teenager, and a coaster is a far better first PLC than a bottling line.

**That is a second and independent argument for the verbatim-standards choices** — CiA 402, IEC 61131-3 spelling, IEC 60204-1 stop categories, the enable handshake. If this taught an invented control language, learning it would be worth nothing outside. Because it is the real interface, what somebody learns here is what they would use in industry. **Fidelity is what makes the on-ramp lead somewhere**, so "close enough" is a worse answer here than it looks.

Evidence the shape works: NL2 has a scripting API most of its users never touch, and it is a ceiling rather than a floor — the professionals who prototype on it are why it has credibility, the hobbyists who never open a script are its volume. And the strategic point underneath: a project that tries to be easy-first competes with Planet Coaster and loses. The stated position is the NL2 gap.

## Current phase: Phase 4 — Track Meshing & Supports (geometry done, art and shell remain)

**Phases 0, 1, 2 and 3 are complete** (Phase 2 closed 2026-08-06 when drag was finally measured). Phase 3.75 is mostly built or deliberately deferred with the reason on its card. **Phase 3.5 is unblocked and not started.**

**Why Phase 4 rather than 3.5, which is the other unblocked one.** The control system is now deeper than anything on the market and **completely invisible in a screenshot** — the track is wireframe, and the evacuation catwalks the developer specified have nowhere to be drawn. For a free open-source project that wants contributors, the thing that recruits them is a picture of a coaster, not a paragraph about CiA 402. Phase 3.5's runtime editor is the *other* defensible answer — it is what turns this from an Unreal project into a program — and swapping them is one line here if that becomes the priority.

**Turnouts and reverse running are DESIGNED, not scheduled** — `Docs/DIRECTION_AND_ROUTES.md`. Two rides prompted it and the developer's framing is the right one: Big Thunder Mountain and Expedition Everest are **casual concepts wearing a mask**, a track merge and a reverse section, and writing either as a ride feature would be the mistake. Three things in it are worth knowing before touching the signalling or the envelope. **Direction is TWO signs, not one** — travel and orientation are independent, and the proposal keeps arc length fixed (a survey does not change because a train is going the other way) while every derived rule asks for `LeadingEdge = Orientation × Travel` rather than assuming a nose. **The sharpest consequence is not in the signalling**: `GEnvelope`'s fore-aft bands are asymmetric 3:1 (`+Gx` 6 g with a headrest, `−Gx` 2 g), so a backwards train has both signs swapped in the rider's frame and is judged against the wrong band — it will pass an unsafe event and report "within envelope" while doing it. And **facing vs trailing is a property of the ROUTE, not the point**: on Everest the same physical point is trailing on the way up and facing on the way back, which is why direction has to land before routes rather than beside them. **Explicitly out of scope**: an elevator-style moving launch platform — a mechanism rather than a topology, and the rule it instances is *rare mechanisms wait; general capabilities do not*.

**Deliberate deferrals, not unfinished work.** Phase 1: the loop side-step (the authored vocabulary cannot express a rideable one — five fixes measured and rejected, see `PHASE0_FINDINGS.md`) and ride-profile trace legibility. Phase 3: turnouts and block topology beyond a closed circuit, parked by the developer as a far-future stretch goal. Phase 3.75: everything script-shaped, waiting on nothing more than a need.

**Do not start a large new subsystem without checking Trello first** — several things that look missing are done, and several that look open are parked on purpose.

What exists now, all of it engine-free and assert-tested under `Prototypes/`, with a thin UE actor over the top:

- **Track geometry** — curvature profile over arc length; straight, arc, clothoid, helix (via constant torsion). `TrackSpline.h`
- **Authored data model and diffable JSON** — stores what was typed, never what was derived. `TrackIO.h`
- **Validation** — report, never repair. `TrackValidate.h`
- **Circuit closure solver** — damped Gauss-Newton over authored parameters. `TrackClose.h`
- **Undo/redo** — snapshots, with the save format as identity. `TrackHistory.h`
- **Train physics and the ride profile** — the whole ride measured at edit time. `TrainPhysics/`
- **Block signalling, wired to the ride, for N trains** — the state machine in `BlockSignal/BlockSignal.h`, and `BlockSignal/RideSignals.h` mapping each train's nose-and-tail arc length onto it. `RideSignals` takes **doubles and a train index, not an `FTrain`**; keep it that way, it is why the whole layer is testable without the physics. The actor derives blocks from the contiguous-zone walk it already did. Three reads carry train identity — the entry test, the exit release, and the permissive — and each one is what stopped a specific silent fail-open; `Tick` is **once per frame, not once per train**. Holding is done by **gating the zone**, never by declining to integrate.
- **Block brakes that actually hold and release** — `FTrain::SetZoneTargetSpeed` retargets a zone at runtime and `FindHoldZoneAt` says where a train may be parked: a device needs **both** authorities, so a trim brake (cannot start a train) and a launch (cannot stop one) are both refused. Whether it can stop the train in the block it has is a separate, layout-only question — `v²/2a` against the block length.
- **A speed trap** — `FSpeedTraps` in `TrackSensors.h`. Two switches a **surveyed** distance apart and a clock; speed is the gap over the time between rising edges, no position and no identity. The gap is read **once at commissioning**, the same idiom as the stop mark consuming train length at survey. Quantisation is a real design constraint and is reported: at 240 Hz a 1 m trap on a 30 m/s train is an 8-tick, **12.5%** bound where a 10 m trap is 1.25% — and what is asserted is the *bound*, because realised error is not monotonic in gap width. **It never trips on the real circuit, and that is the result**: what it buys is the **stopping margin**, which falls from 13.7 m healthy to 5.1 m with one brake dead. A margin degrades continuously where a trip is a cliff.
- **Sensors, and a train counter over them** — `BlockSignal/TrackSensors.h`. `FRideSignals` is HANDED each train's exact span every frame, which is a cheat: a real PLC knows a switch went high and nothing else. `FTrackSensors` is the only layer entitled to a position, reports presence WITHOUT identity (a switch says "metal is over me"), and `FBlockCounter` derives occupancy as *entries at sensor i minus full clearances at sensor i+1* — rising in, FALLING out, which is what stops a block going clear under a straddling train. Proven equal to perfect knowledge over three laps. **A counter must be SEEDED**; lifetime totals send the block behind a train's start to −1. Two kinds of switch exist so far: **block-boundary sensors** (occupancy) and **stop marks** (one per zone, where a trucking train stops). Inputs are scanned **once at the top of the frame** — read inputs, execute, write outputs, as IEC 61131-3 does — so every train is served against the same snapshot. **The counter now runs ALONGSIDE the interlocking as a second, independent means of detection, and a disagreement trips the E-stop** — same blocks, same frame, nothing in common but the answer. That is what a real installation buys with a second detection method rather than a better single one, and it is what makes the sensor layer load-bearing instead of decorative. Also trips on a block counted twice (a collision derived from switches alone) and on one counted below zero (a *lie*: missed trip or bad seed). **Circuits only** — `FBlockCounter` is a counter over a ring, and on an open layout the wrap is false. Measured: both circuits, every train count, agreement on every block on every frame; mutating the falling-edge rule fails it, so the check bites. What still cheats is in `SIGNALLING.md` § "What the system actually knows": the interlocking's own occupancy is still the span (flipping which is primary needs train *identity* inferred from trip order — a rewrite of the safety core, not an addition), and `ServeHolds` still asks `FindHoldZoneAt(GetDistance())`.
- **A station is a PROCESS, not a place** — `BlockSignal/StationProcess.h`. Arrive → unload → load → restraints → all-clear → dispatch, and **the dispatch permissive is now an AND**: blocks clear *and* every station gate. Each gate is a **contact, not a timer** (`FAutoStationCrew` asserts them on dwell timers only because nothing simulates riders, and it is a separate object so it can be deleted). **Readiness is continuous, the release is LATCHED** — those look contradictory and both are load-bearing: a restraint opening in `Ready` drops the permission the same frame, but omitting `Departing` from the permissive **deadlocked the circuit** (released train rolls off its mark → not "in position" → permissive drops → re-braked → parked on its own mark forever, launch drive saw no train in seven minutes). **One process is one POSITION, not one platform**, which is what makes a three-position load platform three of these rather than a rewrite. `ETUSegmentZone::StationUnload`/`StationLoad` exist; an unload platform must NOT require locked restraints (nobody is aboard to close them). **Multi-position platforms work, and were mostly EMERGENT** — no sequencing rule exists or is needed, because a train cannot pass the train in front of it and the interlocking already says "advance when the space ahead frees". Two things did need building: `FTUTrackSegment::bStartsNewDevice` (three loading positions are the same kind at the same speed, so nothing the walk can see tells them apart), and **"loaded" belongs to the TRAIN, not the platform** — riders board once and the train advances full, or every train re-runs the whole sequence at every position and the platform never empties. Measured on three positions: 52 extra seconds of loading at the REAR costs the ride **5.5 s** and does not delay the two in front by a frame; at the FRONT it costs the full **52 s** and everybody pays. **Not built:** turnouts, which the developer has parked as a far-future stretch goal. See `SIGNALLING.md` § "The station". **A backstage buffer is NOT a missing concept** — it is brake sections with drive tyres, one train each, which is a block brake and is already what the model expresses; ten trains stacked is ten trains in ten ordinary blocks. It is a layout decision for one specific ride, not something the general model owes anybody.
- **A run ends where the device changes, and the device is its KIND AND ITS SPEED.** Kind alone was the original rule, and it silently merged a brake at 6 m/s with one at 2 m/s into a single zone targeting 6 — a typed number discarded, which this project treats as a defect everywhere else. It was a logged warning with a wedge-a-different-kind-between-them workaround. Splitting on speed is the smaller and honest rule, and it is what lets several holding devices be authored in a row at all. Same kind *and* same speed still merges, which is correct — that is one device spanning several segments, and it is how every lift hill here is authored. **No preset changed**; every canonical figure is identical.
- **The operator: manual dispatch and an emergency stop.** **The E-stop lives INSIDE `FTrackDrives`** and overrides the *output*, not the command — one layer up it would be a stop with a hole in it the width of every caller that forgot, and the one thing that must never have holes is the stop. **It does not stop trains, it stops the ride**, and that falls out rather than being arranged: open course coasts to the next brake and holds, a brake run stops at once. Measured on the circuit — tripped mid-lap with three trains, every one comes to rest at a device, no violation. Latched, first reason wins, cleared only by a person. **Three conditions trip it that were already detected and only logged**: a signalling violation, a drive fault, a block counted occupied twice. Manual dispatch is ANDed on the end of every other permissive and never instead of one; the button must be **released between trains** (anti-tie-down), and "not pressed" reads differently from "held from the last train". Keys: `[Space]` dispatch, `[Backspace]` stop, `[End]` reset.
- **Stop categories (IEC 60204-1) are now EXPRESSIBLE, which they were not.** `FTrackDrives::EStopCategory`. Cat 0 is immediate removal of power; **Cat 1 is a controlled stop with power RETAINED to achieve it, then removed** — and the second half is the half people drop. **The operator's button is the only Cat 1 on the ride** (`PressEmergencyStopButton`) and every automatic protective trip is Cat 0: a person pressing the button has decided to stop and nothing is known to be broken, where a signalling violation or a faulted drive often means *the thing being asked to perform a controlled stop is the thing that failed*. **The default argument is Cat 0, deliberately** — Cat 1 is strictly the weaker stop, so a call site that forgets to say must get the harder one. Two things make it safe rather than a hole: **the brakes are fail-safe**, so a zone commanded to zero bites and a Cat 0 stops trains rather than merely ceasing to drive them; and Cat 1 carries a **delay timer** (`SetCat1DelaySeconds`, 5 s) because a real SS1 relay does not ask the drive whether it finished, it opens the contactor at the deadline regardless. **Ramps default to off, so on every shipped preset the two categories are identical and nothing measured moved** — the circuit's three-train E-stop measurement is unchanged. `Output()` now guards on *power removed* rather than on *stopped*, which is what lets Cat 1 keep driving while it winds down.
- **Drives, on the output side** — `BlockSignal/TrackDrives.h`. One per zone, and **the PLC's only authority over the ride is to write a command**; how fast the drive gets there is the drive's business. Three numbers that can disagree: `Commanded ≠ Output` is ramping, `Output ≠ Actual` is slipping, `Load = 1` is full torque (free — `Step` already clamps what a zone asks for to what it has). **A fault needs slip AND torque AND time AND not gaining**, and the last term is not optional: a launch is sustained slip at full torque *by definition*, so the first three faulted the real circuit's launch drive on its first dispatch. What separates a launch from a stall is whether the gap is CLOSING. Faults are **reported, never acted on**. **A failed brake is now expressible** — `SetDeliveredFraction` is what the hardware *delivers*, not what it was commanded, pushed to every train's copy of the zone alongside `Output` and multiplying both authorities at the clamp in `Step`. Health defaults to 1.0 and the digest of a full run is bit-identical, so nothing measured moved. What catches a dead device turned out to be **three different answers**: parked on it the ride never dispatches (the stop-mark rule paying for itself), loaded the interlocking and the counter both trip, and **sparse it is simply ABSORBED by the devices downstream and no rule is broken** — a failed brake on a well-laid-out ride is a *capacity and schedule* event, not a safety one, and the detector actually missing is "a train did not stop where it was told". Read the failed-brake section of `FAULTS.md`; an earlier version of this line claimed a runaway that measurement disproved. Ramping defaults to **off** so every pre-drive measurement is unmoved; a ramp only matters if it is slower than the zone's grip. This also ended a per-train wart: zones live on each `FTrain`, so every train used to carry its own idea of what every brake was doing — one drive's output now goes to every copy each frame.
- **A permissive that derives its braking distance** — `FRideSignals::SetHoldingBlocks` says which blocks can hold a train, and a dispatch then clears from the destination *to the next one of those*, because a train in a block with no device in it is committed. The fixed `Lookahead` count is now extra headway rather than the safety rule. **This is what makes the circuit carry four trains instead of colliding at four**, measured both ways.
- **NL2 CSV and telemetry** — validation fixtures, not authoring paths. `NL2Csv/`, `NL2Telemetry/`
- **Starter layouts** — five worked examples of the vocabulary behind a `Preset` dropdown: flat rig, out-and-back, reference, two-train circuit, small batch. Each was measured before shipping. `ATUCoasterRide::PresetLayout`. **`SmallBatch` is the two-train oval re-zoned**, not new geometry — 6 m vehicles, an unload platform and three loading positions, 8 holding places so it carries 7. It is DERIVED from `TwoTrainCircuitLayout()` rather than copied, because the closure is a property of the LEG LENGTHS (leg A is 176 m of flat either way) and a copy could drift from the shape it depends on with nothing to notice. **A preset now brings its train with it** (`ApplyPresetTrainSetup`, explicit load only) — the train is part of the worked example.
- **A device shorter than its train is REPORTED at build time.** The stop mark is `max(start + trainLength, end − clearance)`, so on a too-short device the mark lands *past the far end*, nothing trips it, and a train sent to park there crawls out of its block into the next one. Measured: a 10 m position with a 15 m train gave seven violations in four seconds. Reported, never repaired — clamping the mark back inside builds a device that stops a train with its nose over the boundary, which is worse because it looks like it worked.
- **The ride profile, JUDGED** — `Prototypes/TrainPhysics/GEnvelope.h` puts the profile against the duration-dependent ASTM F2291 / EN 13814 acceleration envelopes. **The limit tables are UNVERIFIED research, not a copy of either standard** (both paywalled), and the header, `PROTOTYPES.md` and the suite banner all say so — bands are *data*, so a verified table is a one-function edit. Four things are load-bearing and each was found by measurement: a limit is a curve against **duration**, so bands are stored inverted (*no run above 4 g may last longer than 1 s*) and the backwards reading silently passes 5.9 g for 3 s; the profile is **resampled to uniform time** first, because arc-length sampling measures the train's speed rather than the rider's exposure; the **5 Hz Butterworth runs forward AND backward**, because a single pass reports the violation half a second downstream on innocent geometry; and an **impact is reported only when the sub-0.20 s exemption is what saved it**, or every ride reports wobbles over the 1 g band it rests at. **Report, never repair.** Its real-ride test **asserts the train completed** — that is not decoration, the suite reported "within envelope, zero findings" three times over a train that stalled at 46 m, and a conformance verdict on a ride that did not happen is the one failure this tool must not have.
- **The canonical figures, reproducible** — `Prototypes/TrackSpline/reference_figures.cpp` prints everything `Docs/REFERENCE_LAYOUT.md` publishes. Run it before quoting a number from that page.

- **The track, as geometry you can see** — `Prototypes/TrackMesh/`, and Phase 4's first piece. `WalkTrack` is the ONLY thing that touches an `FTrack` and it walks with `AdvanceFrom`; `BuildTrackMesh` takes the frames and has no `FTrack` at all, which is what makes the O(n²) trap **unreachable rather than discouraged** — the vertical slice's debug draw had exactly that bug, ~118 M integrator steps at BeginPlay. Rails, spine and ties are three buffers because they are three materials, and a tie is **two struts rail-down-to-spine** rather than one bar across, because a real cross-tie is a truss and a bar would pass through the train. Every assertion covers geometry that LOOKS plausible: **inside out** (found one immediately — `Cross(along, around)` is *minus* the radial normal where `Tangent × Lateral = Up`), the **UV seam** (a ring closes, its texture coordinate does not), and a **curve tighter than half the gauge** folding the inner rail through its own axis, reported never repaired. **THE PORT RULE IS NEW AND IS NOT IN THE CONVENTIONS SECTION BELOW:** `M(x,y,z) = (x,−y,z)` is a REFLECTION with determinant −1, so it **reverses triangle orientation** — mirror positions and normals alone and every surface is inside out in UE while every vertex position is correct. Two indices of every triangle swap at the boundary. **Open ends are CAPPED, and a circuit's are not** — on a closed layout the first ring and the last are the same ring, so a cap there is a disc buried in the seam, coplanar with what is either side of it. `bCapEnds` follows the *measured* `bTrackIsCircuit`. **Ties are capped either way**, because a strut has two free ends by definition and that is where it showed: every tie was a length of open pipe with both ends in shot at once. Asserted by **signed volume and watertightness**, which is stronger than the winding check it joins — a closed mesh encloses positive volume only when every triangle faces outward, so one reversed cap drops it by two thirds, and reversing one is asserted to be visible. A 1288 m circuit at 0.5 m / 12 sides is 234,533 vertices and 309,192 triangles; **caps cost the ties double** (a 12-side cap fan is as many triangles as a two-ring strut's wall), which is the whole +25%.

- **Supports, and where one must NOT go** — `Prototypes/TrackMesh/TrackSupports.h`. Placement is a constraint problem with no single right answer, so this places what the obvious rules allow and **REFUSES the rest with a reason** — the conclusion the evacuation walkways reached. **Spacing is a SPAN, not a sample count** (asserted by changing the walk spacing and getting the same bent count). Track under grade gets nothing rather than a column of negative length; **at grade is silent, because that is a station**. Through an **inversion the spine is ABOVE the track**, so a column from underneath would pass through the rails — detected from the frame's own up vector. And **a column must not pass through the track**, the classic failure, asserted both ways: a return leg over its own outbound refuses all 48 m above it, a plain hill refuses nothing. **Findings merge into RUNS by KIND** — merging on the message looked right and was not, because every fouling finding names the metre it fouls at, so nothing ever matched. The **longest unsupported run** is reported, because a placer that reported only what it placed says nothing about the hole its refusals left. Ground is a **function**, so Phase 5's terrain is a swap.
- **The shell, engine-free wherever it has an answer that can be wrong** — `Prototypes/Shell/`. The **camera**: framing checks BOTH axes (the distance that fits a box vertically is not the one that fits it horizontally, so a long low layout hangs off the sides of an ultrawide) and uses the bounding SPHERE so orbiting cannot lose the subject; the **near plane follows the camera**, because a 90 m lift and a 2 cm bolt cannot share a fixed one; pitch CLAMPS rather than wraps; zoom is MULTIPLICATIVE; and smoothing is **frame-rate independent**, so the camera does not feel different on a better machine. The **diagnostics panel**: report-never-repair made structural — a row has a place to GO and no action to TAKE, so there is nowhere to wire a fix button — **height gets its own row and says LOW or HIGH** (the vertical slice shipped 8.5 m low because plan view looked closed), a ride that does not complete **hides every derived number** (the envelope suite's own old failure), and **saving is never blocked**. The **segment editor**: `EditConditionHides` reimplemented, and **hidden is not deleted** — the naive version clears a value when its field stops being relevant, so flipping Arc→Straight→Arc loses the radius; multi-select shows the INTERSECTION and flags a differing value rather than showing the first (which people then edit on top of); and the **undo merge key** `TrackHistory` says is the UI's to supply, broken for free by any structural edit. The **graph**: nice-number ticks AND a range grown to a multiple of the step, zero kept on screen for signed channels, a dead-flat channel given an axis rather than a NaN, and a scrubber that round-trips exactly. The **browser**: a file that will not load still gets a row **carrying the loader's reason**, and a missing file **stays in the list marked** rather than being pruned, because the commonest cause is an unplugged drive. And the **session and settings**. **Dirty is a COMPARISON, not a flag**: undo back to the saved text and the document is clean, which is only affordable because the save format is already the identity. **Autosave writes a SIDECAR and never the document** — overwriting on a timer is data loss with extra steps — and does not run on a clean document. **Crash recovery is OFFERED at BOOT, never applied**, because opening anything would overwrite the evidence, and an accepted recovery is **DIRTY** or somebody loses the same work twice. Going back to the menu asks; Build↔Operate↔Ride never does, because nothing is discarded. **`EditsAllowed()` is true in BUILD and nowhere else — constraint 1 one level up.** In settings, **a default is not a value** (only explicit choices are written, so improving a default reaches everybody who never touched it) and **unknown keys survive**, so running an older build once does not silently reset what a newer one added.

The editor surface is Unreal's Details panel over `TArray<FTUTrackSegment>`, with a live viewport preview and ride-profile traces. That is not a placeholder for a Slate UI — see the numeric-entry card for why.

**Phase 2's bar is "feels right to an NL2 veteran."** The thing this file used to send you at — the train being a point with no length — is **done**: `FTrainConfig::TrainLength`, nine sample points, gravity reading the train's *mean* height. Two claims that went with it have since been measured and were wrong, so do not repeat them. The back car is only thrown harder on an **asymmetric** hill, and on a symmetric one there is no difference at all. And train length does **not** explain the `DragK` fit — the two coefficients were never separable, correlation 0.975, so that split is a free parameter rather than a result.

Two trains on one circuit is **done** (2026-08-03) and the actor runs them, so do not go looking for it. `Prototypes/TrainPhysics/test_twotrains.cpp` is the proof, and the last test in it is a line-for-line stand-in for `ATUCoasterRide::Tick` — that exists because the actor cannot be compiled without Unreal, so its dispatch policy has nowhere else to be checked. **If you change the actor's tick order, change that test with it or the policy is unverified.**

**A real ride's brake count is not its block count.** Three different things sit on the track and all look like a brake: **block brakes** (interlocking — the only ones that bound a block and the only ones the capacity formula counts), **evacuation zones** (getting riders *off*, which needs a walkway and an egress route, not just a way to stop), and **safety catches** (anti-rollback; passive, fails closed). A large ride can have ~25 evacuation zones and a handful of catches while running far fewer trains than either count.

- **Anti-rollback is built** — `FTUTrackSegment::bAntiRollback`, derived into spans exactly as zones are. Deliberately **not** a zone (a zone is a *control* device with a speed and something commanding it; a catch has neither, and overlaps zones freely because a lift hill is both at once) and **not** a block boundary (it cannot release a train, so it is no more a place to park one than a trim brake is). A caught train is *arrested*, not merely stopped from moving — otherwise it keeps its backward velocity while pinned, which no hardware can do.
- **Evacuation zones are not modelled**, and want walkway geometry that does not exist until Phase 4.

What is actually worth starting on:

1. ~~A fast reference recording from NoLimits 2.~~ **DONE 2026-08-06, and both coefficients are now measured rather than derived.** A dead-flat straight launched to 142.5 km/h and coasted 1350 m: `DragK` = **0.000100** (the derived 0.00045 was 4.5× too high) and `Crr` = **0.026**, a 0.04% fit. Applied the same day; the only assertion that moved was the mid-course entry speed on the two-train circuit, 26.5 → 30.39 m/s. **Nothing geometric changed and every dynamic figure did** — before quoting any speed or G number from an older doc revision, check it against `PHASE0_FINDINGS.md` § "Validation against NoLimits 2".
**RESTRAINTS AND GATES ARE COMMANDED DEVICES** (`FCommandedBank`, one instance each), not a dwell timer: commanded position, travel time, and a count of separately-sensed **groups**, with locked meaning EVERY group reports locked. That is what makes "commanded closed but car 3 is not locked" expressible — the failure a walk-round exists to find, and one a single bool could not say. Travel time is HARDWARE, not crew allowance, so securing takes the longer of the walk-round and the bars. The crew OWNS the banks, so no caller of `Serve` changed. **The all-clear is now two contacts and a walk-round** — bars down, gates shut, and an operator who has looked — so any one of the three outstanding holds the dispatch, and a jammed gate holds it for ever rather than being timed out of the way.
**PRE-LAUNCH IS BUILT.** The permissive carries a third term: the device you are dispatched *into* must be **ready**, not merely clear — a launch armed, a chain turning. `FTrackDrives::IsReady` is `Commanded == Output && !faulted`; a drive still ramping is not ready, and those states were distinguishable for free the moment a command stopped taking effect instantly. **Plain track is always ready** — a term that denied a dispatch onto open course would stop the ride rather than protect it — and an E-stopped ride is ready for nothing. Ramps default to off, so every shipped preset satisfies it in one frame and nothing measured moved; give a launch a real ramp to see it.

**THE CONTROLLER IS A MACHINE NOW, not an implication** (`BlockSignal/PlcUnit.h`). `FRideSignals` plus `ServeHolds` is the PLC *program*; `FPlcUnit` is the PLC — the same gap the drives had before `FTrackDrives` and the sensors had before `FTrackSensors`, and closing it is what turned each of those from correct-looking into able to disagree with itself. It owns four real operational states the model could not express: a **key switch** (RUN / PROGRAM / STOPPED, where PROGRAM is the honest home for "maintenance is working on it"), a **watchdog** (the scan overrun the accumulator already detected becomes a latched FAULT rather than a logged note), a **program identity**, and **power**. **THE STANDARD PLC, NOT THE SAFETY CHAIN** — it may withhold permission to run and has no authority to prevent a stop, because the E-stop is inside `FTrackDrives` and the brakes are fail-safe, so neither routes through it. That is constraint 7 made structural, and `test_plcunit.cpp` asserts it against the real drive layer rather than by reading the code. `OutputsEnabled()` **permits, it does not compel**: false means the controller commands nothing, and a device with no command falls to its safe state exactly as it would with the cabinet unplugged. Two things fall out that were previously unimplementable. **Block state is not trusted across a power cycle** — the Tier 1 card asked for a course-clear walkdown and operator reset, which only means anything once something can be switched off. And **a program built for a different layout refuses to RUN**: the identity is a digest of the *derived blocks and zones* rather than the authored segments, so a geometry tweak that moves no boundary does not invalidate it — and it is the first detector this project has ever had for "I changed the code and the editor is still doing the old thing". Defaults are RUN, powered, walked, matching, so every measured figure is unmoved.

**THE GENERATED DEFAULT PROGRAM IS BUILT** (`BlockSignal/PlcProgram.h`). One POU per HOLDING device — a trim cannot start a train and a launch cannot stop one, so neither has a dispatch permissive to override. **The generated text IS the real permissive**, not an illustration: the same AND `ServeHolds` builds, with the station's three contacts and its walk-round spelled out rather than hidden behind one `ready` flag. **Every generated permissive is asserted to PARSE AND BIND in its own language** — a tutorial that does not compile teaches the wrong thing. **AN OVERRIDE IS PER BLOCK AND NEVER A MODE**, which is the NL2 lesson: their fatal choice was that scripted mode disables automatic block mode entirely, so customising one brake costs 500+ lines and the whole ride. **A broken override keeps the author's text, runs the generated default, and says so LOUDLY** — the third of three options, because rejecting the edit loses work, running an unparsed block loses a train, and a block silently running its default while its author believes otherwise is worse than either. **Regeneration never touches an override**, overrides are carried by NAME not index (an inserted device shifts every index and must move nobody's work), and **an orphaned override is REPORTED rather than eaten**.

**TIER 1'S WIRING IS BUILT** (`BlockSignal/SafetyIo.h`). `FTrackDrives` held the E-stop and its stop categories; this is everything BELOW that, which had been plain booleans. **DE-ENERGISE TO TRIP:** a safety input is a CIRCUIT carrying current while all is well, so a stop is demanded by the ABSENCE of current — a broken wire, a pulled connector, a dead supply and a pressed button are the same signal, and nothing has to know which. **Two channels of OPPOSITE polarity**, because one channel fails to danger in exactly one way (a short to the supply reads energised for ever, so a pressed E-stop does nothing) and doubling it does not help — the fault that makes one read safe makes the other read demanded. That is diversity rather than redundancy. **A stop is EITHER channel, not both**; a pair requiring agreement is a system where one broken wire disables the E-stop. The **discrepancy window** exists because two contact blocks never switch on the same millisecond — 50 ms of disagreement is normal, a second is a latched fault. **EXTERNAL DEVICE MONITORING closes the welded contactor**, which `FAULTS.md` had listed as caught by nothing: mirror contacts wired NC into the reset circuit, so the reset is a question the machine answers and a welded contactor can never be talked past. **The relay carries instantaneous AND delayed outputs, and Cat 1 is impossible without both** — contactors that open instantly leave nothing to ramp with. **A restraint fails the other way and that is not an exception**: fail-safe was never "de-energise", it is *fail to the state that cannot hurt anybody*. **Not modelled:** OSSD pulse testing, cross-relay monitoring, PL/SIL arithmetic — how an installation *proves* a category rather than implements one.

**The drive is a CiA 402 state machine** (`BlockSignal/Cia402.h`), and implementing it as specified IS the real thing rather than a model of one — IEC 61800-7-201/301 over EtherCAT as CoE is the actual interface behind Beckhoff, KEB, SEW and Elmo. Eight states, of which **only Operation enabled produces torque**, which is the whole reason a drive has eight rather than a bool. Four things carry the authenticity for almost no code and each is asserted: **the enable handshake cannot be skipped** — writing `0x000F` at a disabled drive does nothing for ever, because a PLC must write Shutdown, *wait for the statusword*, write Switch on, *wait*, then enable; **quick stop is ACTIVE LOW**, so a zeroed controlword — a dead master, a pulled cable — commands a stop rather than nothing, which is de-energise-to-trip expressed in a fieldbus word; **a fault reset needs a RISING EDGE**, so an operator holding it waits for ever, the same anti-tie-down shape as the monitored E-stop reset; and **a fault is not instant**, the drive running its configured reaction (605Eh) before it settles. The statusword is **derived from the state, never stored beside it** — a stored copy is a second truth. `FTrackDrives` owns one per drive and **drives it from decisions already made rather than in parallel**, so the two cannot disagree; the maintenance panel shows the statusword instead of the four states this project invented. The stop categories map straight on: **Cat 0 is STO** (voltage away, coast) and **Cat 1 is SS1** (quick stop ramp, then voltage away) — IEC 61800-5-2 and this project's own E-stop describe the same two paths.

**SHOW CUES: THREE TIME MODELS, AND THEY COMPOSE** (`BlockSignal/ShowCues.h`). **Timecode** (a master clock, restartable anywhere, tolerant of one subsystem dying), **relative offsets**, and **triggered chains** — the last being the glue between a NONDETERMINISTIC ride and DETERMINISTIC shows, and the reason a coaster's show system is not one long timeline. The ride is a triggered chain at the top; each scene is clock-driven for its 10-40 s life; idle and ambient loop and are **pre-empted by priority rather than mixed**, because two sequences driving one fixture is a fight. **FOLLOW IS NOT HANG**, and conflating them is the single most common real show-programming bug: time from the previous cue's START versus from its COMPLETION. Both are modelled separately and the difference is asserted the only way it shows — **edit a duration by 2 s and follow moves nothing downstream while hang moves everything**. **Drop-frame drops NUMBERS, not frames**, which everybody gets backwards: an hour of 29.97DF lands at 3599.996 s where the naive conversion is 3.6 s late. **A loop's period is the last cue's FOLLOW, not its duration** — the first version used duration and made a one-second loop fire every 100 ms, and the loop is asserted drift-free over ten minutes.

**THE EFFECT DEVICE LAYER IS BUILT** (`BlockSignal/DmxFixtures.h`). `FShowBus` decides what fires; this is what it fires INTO. DMX512 modelled **literally but INTERNALLY** — universes, 512 slots, a start code, fixtures at addresses — with **no network I/O, ever**: a sim that drove real fixtures would be a lighting console with a coaster attached. **DMX HAS NO FADES**, which is the fact people get wrong: a packet is absolute values and the console computes every intermediate one, so a full 513-slot packet is 22.7 ms and **44 Hz is the hard ceiling** (24 slots is 784 Hz — shorter packets go faster, which is why a small rig's strobe looks smoother). Addresses are **1-based twice over**, within the universe and within the fixture, and slot 0 is the start code and not a channel. **Overlapping fixtures are REFUSED**, never shuffled — the symptom is a light that flickers when a different one is cued and nobody traces it to addressing. **Data loss is selectable and both choices are defensible**: shutdown for haze, hold-last for architectural, and hold-last is WRONG for anything hazardous. **ARM PLUS LEVEL** is the characteristic shape of effect gear and exists so one stray channel cannot start an effect. **A DUTY CYCLE is enforced by the DEVICE, not the cue** — an operator holding a fader down does not get 30 s of flame, and putting that rule in the cue layer would let a bad cue destroy hardware. A **10 s igniter warm-up DROPS cues rather than queueing them**, because firing a flame effect ten seconds late is worse than not firing it. **Flame is not fired by the show controller at all** (NFPA 160: a safety-rated controller and a human-held positive enable sit between the request and the gas).

**The generated control panel is BUILT** (`ATUCoasterRide::DrawControlPanel`, `[P]` in play, debug canvas so it needs no asset). It walks the same block and zone lists the geometry and physics walk: a block becomes an indicator, a powered run a VFD module, a platform a sequence readout. Every number is read live — nothing is cached or computed for display, so it cannot drift. **Corrected against photographs of three real operator consoles**, and `SIGNALLING.md` § "What three real consoles taught it" records what they changed and the list of controls they have that this does not — do not add a lamp for one of those without modelling it first. Two things worth keeping: the block strip gives every block a **minimum width** (strict proportion made four 10 m platform positions three pixels on a 1288 m circuit), and there is no yellow lockout band because lockout is not modelled.

**It has TWO VIEWS, and the split is a real one rather than a detail level** — `ETUPanelView`, `[P]` cycles operator → maintenance → off. Every installation has both: an operator dispatches trains, a maintainer diagnoses machines, and **motor current belongs to exactly one of them**. So the drives section is the one place the views genuinely disagree — the operator gets one state word per drive (`RUNNING` / `RAMPING` / `FAULT` / `STOPPED`, all facts a drive holds about *itself*), and maintenance gets commanded-vs-output-vs-motor, torque, and fault acknowledgement. Maintenance also gets the **second detection method's own per-block counts** under the schematic, plus a `DETECTION` line that states the agreement — because a cross-check never *seen* to agree is indistinguishable from one that is not running. **Not a difficulty setting**: nothing is dumbed down and nothing is invented, the same live reads are asked two different questions. `Docs/UI_CONVENTIONS.md` records why a "reskin"/mod layer was rejected in favour of this.

**Where a held train parks is settled, it is not the middle, and A SWITCH SAYS SO.** Each zone carries a **stop mark** at `deviceEnd − HoldNoseClearanceM` (1 m) and the dispatcher's whole rule is *truck forward until the mark trips* — no train length, no arc length, no zone extent, because a PLC has none of those three. Measured from the end and applied to the nose, because the margin exists to stop a train protruding into the next zone through a defect. Train length is consumed **once, where the mark is placed**; putting it back into the dispatcher is undoing the point. The brake does not put the train there — it stops it well short and the drive tyres truck it the rest of the way, up to 67.3 m on the mid-course brake. Measured at all five devices: mark 1.00 m short, nose parks 0.18 m past it, **0.81 m clear**, identical everywhere because the overshoot is `v²/2a` at the crawl speed and grip. Changing any of this is changing a safety margin: read the holding section of `SIGNALLING.md` first.

**The scan runs at a FIXED PERIOD, not once per rendered frame** (`ATUCoasterRide::SimStep`, `SimHz` = 240, an accumulator in `Tick`). It used to run at frame rate, which was wrong twice: **unfaithful**, because a PLC scans on a fixed period and does not go faster when the graphics card is idle — every rate in the control system moved with the frame rate, and the documented "a train can cross a sensor inside one scan" limit was quietly *worse* on a slow machine; and **not reproducible**, so nothing could be recorded and replayed and no fault-injection scenario could prove anything. On a backlog past `MaxStepsPerFrame` the time is **DROPPED, never worked off** — catching up means running the ride faster than real time, and a ride that fast-forwards through a hitch can skip a train past a block boundary. Reported as a scan overrun, which is what a real controller does with a missed deadline. This also makes the actor and `test_twotrains.cpp` step at the same rate, so "line-for-line stand-in" is true rather than aspirational.

**Trains run real laps, and `bCircuit` is MEASURED, never authored.** The actor checks position, heading and roll at the seam on every rebuild and only wraps a layout that passes; the other three presets still return to the station by teleport, which is correct for track whose two ends are hundreds of metres apart. Read the lap entry in `PHASE0_FINDINGS.md` before touching it — `S -= TotalLength` is one of four changes, and the other three (distance travelled, the sample walk across the seam, and what a reversed rear/front pair *means*) are each a silent failure if missed.

**A circuit closes by SHAPE, not by solver, and the shape is load-bearing.** An oval closes analytically when both turns are the same way, exactly 180°, same radius, same easement; the only condition left is that the return leg's horizontal extent equals the two collinear outbound legs'. That condition means **every metre spent outbound is paid for twice**, which is why the turnaround sits at the top of the hill rather than at each end — measured, the obvious layout came to 1717 m and stalled in every variant. See `PHASE0_FINDINGS.md`.

Before quoting any number from this project, check whether something already measures it — `reference_figures.cpp` for the reference layout, `test_twotrains.cpp` for the closed circuit (it prints its canonical figures on the way out), the assert suites for the models, `PHASE0_FINDINGS.md` for what has already been disproved. Several plausible fixes on that page were measured and rejected, and re-proposing one without saying why yours differs wastes everybody's time.

## Key vocabulary (used throughout the docs and should be used consistently in code/comments)

`Docs/GLOSSARY.md` explains these and the geometry terms (curvature profile, clothoid, parallel transport, holonomy, torsion, Darboux vector, felt G) in terms of what they are on a real coaster. The list below is the short form for code consistency; the glossary is for understanding what the words mean.

- **Block buffer / overlap** — the safety-margin state a block holds after a train physically exits it, before it reports CLEAR. Named after the real-railway "overlap" signaling concept.
- **Heartline** — the reference line (not the rail centerline) that banking and ride-camera calculations are computed around, so felt-G through banked turns is physically correct.
- **Roll vs bank** — not synonyms, and the difference is a per-segment mode (`ERollMode`). **Roll** is measured from the rotation-minimising path frame: defined everywhere including inverted and vertical track, and what the integrator sees. **Bank** is measured from the horizon — what a spirit level reads — and is undefined pointing straight up. Say which one you mean; `Roll = 0` is not level on non-planar track.
- **Dispatch permissive** — the logic gate that allows a station/launch to release a train, based on downstream block clearance (and, for high-speed sections, braking-distance lookahead).
- **PLC vs VFD** — not interchangeable, and it is an easy slip. The **PLC** is the brain: reads sensors, holds block state, evaluates permissives, commands devices on a scan cycle. A **VFD** is the muscle for *one* motor: it takes a speed command and drives a tyre or chain to it. There is one PLC and many VFDs. **`FRideSignals` plus `ServeHolds` IS the PLC program** — that is the right way to think about what has been built. `Docs/CONTROL_ARCHITECTURE.md` has the tier split and the IEC 61131-3 grounding.
- **VFD module** — the generated control-panel element for one drive on a powered segment (lift chain, tyre launch): target frequency/speed, actual motor feedback, torque/current draw, ramp rate.
- **Block brake vs trim brake** — a block brake is a friction pad *and* drive tyres: the pad trips on entry and stops the train as hard as rider comfort allows, then the tyres convey it to a holding position. A trim can only slow a train, so a train parked on one stays there. Only block brakes bound a block or count toward capacity.

## Conventions in prototype code

The prototypes are metres, radians, seconds, and a **right-handed** frame where `Tangent × Lateral = Up` and `+Lateral` is the rider's **left**. UE5 is centimetres and **left-handed** with `+Y` to the right.

Convert units *and* flip handedness at the port boundary, never inside the math. The flip is not a single sign: UE's `Right` is `-M(Lateral)` where `M(x,y,z) = (x,-y,z)`. Getting this wrong mirrors the entire track and produces geometry that still looks self-consistent — `Docs/PHASE0_FINDINGS.md` has the measured residuals.

**And M is a REFLECTION, so it reverses triangle winding.** Determinant −1. Anything with an index buffer must swap two indices per triangle at the boundary or it is inside out in UE with every vertex position correct — invisible under backface culling, black under a light, and nothing in the engine-free suites can ever see it. Asserted as a property in `Prototypes/TrackMesh/test_trackmesh.cpp`.
